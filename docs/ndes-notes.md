# NDES notes

Working notes from the lab where this kit was developed. Hostnames, addresses and
account names have been replaced with placeholders; the topology and the reasoning
are unchanged.

---
===============================================================================
 NDES SERVER  -  NDES EXERCISE
 Label: ndes     Scenario: (none - the default patterns are NDES-focused)
 Account: administrator, PowerShell "as administrator"
===============================================================================

 The label must be the same as on the AD server (ndes).

 Kit location assumed below:  C:\Tools\ndes-backup-and-restore

 This host captures its OWN local state:
   - HKLM\SOFTWARE\Microsoft\Cryptography\MSCEP   <- the NDES configuration
   - SCEP application pool + /certsrv/mscep vdirs (IIS)
   - certificates, services, features, firewall
   - applicationHost.config as installed

 The directory writes (the SCEP service account's published certificates, and
 any rights it is granted) are captured on the AD server - see AD-NDES.txt.

-------------------------------------------------------------------------------
 BEFORE  -  before you add the NDES role service
-------------------------------------------------------------------------------

cd C:\Tools\ndes-backup-and-restore
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force

# 1. Take the baseline (T0).
.\Start-NdesCapture.ps1 -Label ndes

   Expected last lines:
     baseline complete - 0 collector(s) failed
     state: C:\NdesCapture\NDES\state-ndes.json

   Pause at "collect registry" is normal. Let it finish.

   Now run the NDES setup:
     - install the AD CS Network Device Enrollment Service role service
     - run the NDES configuration wizard, pointing it at the CA
       (CAConfig: ca.contoso.com\Lab-CA, or whatever your CA CN is)
     - run it all the way through, including the RA certificate enrolment

-------------------------------------------------------------------------------
 AFTER  -  once NDES is installed and configured end to end
-------------------------------------------------------------------------------

cd C:\Tools\ndes-backup-and-restore
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force

# 2. Close the capture window (T1).
.\Stop-NdesCapture.ps1 -Label ndes

# 3. Build the report.
.\Compare-NdesCapture.ps1 -Label ndes

# 4. Read it.
notepad C:\NdesCapture\NDES\report-ndes\report.md

-------------------------------------------------------------------------------
 WHAT YOU SHOULD SEE
-------------------------------------------------------------------------------

 In C:\NdesCapture\NDES\report-ndes\report.md:

   ## MSCEP configuration as installed
     HKLM\SOFTWARE\Microsoft\Cryptography\MSCEP
       CAServer            = <CA>\<CA-NAME>
       CertificateTemplate = IPSECIntermediateOffline
       SigningTemplate / EncryptionTemplate
       SigningCertHash / EncryptionCertHash / CACertHash
       ValidityPeriod, ValidityPeriodUnits, RenewalPeriod

   ## High-signal changes  (Registry)
     ...\Cryptography\MSCEP  (new values)
     ...\Services\SCEP       (new service key)

   ## High-signal changes  (IIS)
     APP_POOL SCEP added
     VDIR mscep and mscep_admin added

   ## Roles and features
     ADCS-Device-Enrollment: Available -> Installed

 IMPORTANT for the rebuild scripts: MSCEP mixes two kinds of value.
   policy  -> CertificateTemplate, SigningTemplate, EncryptionTemplate,
              ValidityPeriod, RenewalPeriod, UseSinglePassword
   state   -> CACertHash, SigningCertHash, EncryptionCertHash
 Restore the policy values; let the hashes be regenerated by the install.
 They point at certificates that will not exist on a new server.

 Handy extract for the restore script:

   Import-Csv C:\NdesCapture\NDES\report-ndes\changes.csv |
     Where-Object { $_.Target -match 'MSCEP' } |
     Format-Table Change,Name,Before,After -AutoSize

-------------------------------------------------------------------------------
 TROUBLESHOOTING
-------------------------------------------------------------------------------

 "capture-settings.psd1 is missing" / "Module not found"
     Copy the whole kit folder, not just the .ps1 files.

 IIS section empty
     IIS was not installed at T0. NDES setup installs it, so the T1 side will
     show the new app pool and vdirs.

 Report shows no IIS section at all
     Check compare.log - the "iis" collector is skipped when appcmd.exe is
     absent.

 DON'T: interrupt Start; run Stop before NDES is fully configured.
